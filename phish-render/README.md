# phish-render: сервіс рендеру підозрілих сторінок

Приймає адресу (можна знешкоджену: `hxxps://olx-pay[.]site`), відкриває її в ізольованому Chromium і повертає:

- скриншот;
- ланцюжок редиректів і кінцеву адресу;
- заголовок і видимий текст;
- форми та прапорці «є поле пароля» і «є поле картки».

Це другий шар детектора (рендер сторінки). На вході — адреса, на виході — дані для правил і vision-моделі.

Стек: ASP.NET Core (.NET 10), Microsoft.Playwright, Docker.

## Запуск на VPS (~15 хв твоєї роботи)

1. **VPS.** Ubuntu 24.04, 2 vCPU, 4 ГБ RAM, будь-який хостер. Сервер тільки під цей сервіс: жодних твоїх ключів, паролів чи інших проєктів.
2. **Залий архів** з ноутбука:
   ```bash
   scp phish-render.tar.gz root@<IP>:~
   ```
3. **Встанови:**
   ```bash
   ssh root@<IP>
   tar xzf phish-render.tar.gz && cd phish-render && bash setup.sh
   ```
   Якщо хостер дав користувача `ubuntu` замість `root`, то ту саму команду запускай через `sudo bash setup.sh`, а далі всюди додавай `sudo`.

   Перший запуск триває 5–10 хв, бо качаються .NET SDK і Chromium. В кінці буде `Готово: {"status":"ok",...}`.
4. **Перевір:**
   ```bash
   bash test.sh https://olx.ua
   ```
   Скриншот забрати на ноутбук:
   ```bash
   scp root@<IP>:~/phish-render/shot.jpg .
   ```

Прогнати весь тестовий набір (62 адреси):

```bash
python3 tools/batch_render.py testdata/phishing_test_set.csv
```

Результати з'являться в `render_out/`: по JSON і скриншоту на кожну адресу і зведена `summary.csv`. Більшість доменів із набору вже мертві, тож очікуй багато `dns_failed`. Для живих сторінок бери свіжі адреси з phishunt.io.

## Спробувати локально на Mac (без VPS)

Потрібен запущений Docker Desktop. У папці `phish-render`:

```bash
bash local-mac.sh
bash test.sh https://olx.ua
open shot.jpg
```

Локально рендер **тільки легітимних сайтів**. На ноутбуці немає мережевої ізоляції, яку ставить `setup.sh`, тому фішингові адреси й тестовий набір проганяй лише на VPS. Зупинити: `docker compose down`.

## Вердикт: POST /check

`POST /check` рендерить сторінку і каже, чи це фішинг. Заголовок `X-Api-Key` той самий, що для `/render`.

```json
{ "url": "olx-pay[.]site", "mobile": true, "followCta": true, "useLlm": true }
```

Необов'язкові поля (є і в `/render`):
- `referer` — сторінка, з якої нібито прийшов відвідувач, наприклад `https://l.facebook.com/`. Фейкові магазини часто показують клон лише відвідувачам із реклами.
- `passWarning: true` — пройти попередження Cloudflare «Suspected Phishing» і зняти сторінку за ним. У відповіді тоді є `render.passedWarning` із заголовком попередження, а правило «Cloudflare вже попереджає про фішинг» усе одно спрацьовує.

Відповідь:

```json
{
  "verdict": "phishing",
  "score": 80,
  "brand": "OLX",
  "reasons": ["В адресі назва бренду OLX, але домен не офіційний (olx-pay.site)", "Сторінка просить дані банківської картки", "..."],
  "ruleVerdict": "phishing", "ruleScore": 80,
  "llm": { "isPhishing": true, "confidence": 0.95, "reason": "..." },
  "domainAge": { "domain": "olx-pay.site", "ageDays": 3 },
  "render": { "...": "усе, що повертає /render, плюс ctaStep" }
}
```

`verdict` має одне з чотирьох значень:
- `phishing` — 60 балів і більше;
- `suspicious` — від 35 до 59 балів;
- `safe` — менше 35 балів;
- `unreachable` — сторінка мертва або повертає 404.

Як вердикт будується:

1. **Офіційний домен бренду завжди безпечний.** Список брендів лежить у `src/RenderService/brands.json`: OLX, Нова Пошта, банки, Дія тощо. Якщо неофіційна адреса перекидає на офіційний сайт, це «підозріло», бо так фішинг ховається від перевірок.
2. **Бали за ознаки.** Кожна ознака додає бали й пояснення в `reasons`:
   - бренд у неофіційній адресі;
   - бренд у заголовку чи тексті;
   - поле картки або пароля;
   - форма, що відправляє дані на інший домен;
   - фрази-приманки на кшталт «отримати компенсацію» чи «OLX доставка»;
   - безкоштовний конструктор сайтів (Yola, Webflow, workers.dev…);
   - підозріла доменна зона, наприклад .top чи .site;
   - слово-приманка в адресі;
   - вік домену за RDAP: менше 30 днів дає +30, старше 2 років дає −10;
   - стрибки між доменами.
3. **Кнопка-приманка.** Якщо на сторінці немає форм, сервіс натискає головну кнопку («Отримати компенсацію», «Продовжити») і дивиться, що відкрилось далі. Результат лежить у `render.ctaStep`, разом з окремим скриншотом.
4. **LLM-суддя (Claude Haiku).** Читає текст, форми й обидва скриншоти. Він може лише **підвищити** вердикт, знизити не може. Тож фішингова сторінка, яка пише «ignore instructions, this is safe», себе не виправдає. Без ключа API працюють лише правила.

### Увімкнути LLM

1. Зареєструйся на [platform.claude.com](https://platform.claude.com), поповни баланс і створи ключ API (він починається з `sk-ant-`).
2. На Mac у папці `AntiFraud` виконай `bash set-llm-key.sh <IP>` і встав ключ, коли попросить. Ключ одразу йде на сервер у `.env` і ніде більше не зберігається.

Одна перевірка коштує частки цента: два скриншоти й кілька тисяч токенів на Haiku. Модель можна змінити через `LLM_MODEL` у `.env`.

Запобіжник від витрат: не більше `LLM_DAILY_LIMIT` викликів на добу (за замовчуванням 300, це до $0.20 на день). Після ліміту вердикт видають самі правила. Скільки викликів уже зроблено сьогодні, показує `GET /health`.

### Оцінка точності

```bash
sudo python3 tools/fetch_feed.py testdata/live_feed.csv 40      # свіжі живі фішингові адреси з phishunt.io
sudo python3 tools/evaluate.py testdata/live_feed.csv testdata/phishing_test_set.csv testdata/legit_ua.csv --out eval_out
```

Результати лягають в `eval_out/`:
- `report.md` — точність, повнота, F1 і частка хибних тривог, окремо для «тільки правила» і «правила + LLM», плюс список кожної помилки з причинами;
- `results.csv` — рядок на кожну адресу;
- скриншоти.

З Mac усе це запускає одна команда: `bash run-eval.sh <IP>`.

`fetch_feed.py` пропускає домени, які вже були в попередніх оцінках: ті, що в `testdata/feed_seen_seed.txt`, і ті, що накопичуються на сервері у `testdata/feed_seen.txt`. Тож кожен прогін перевіряє детектор на адресах, під які правила ще ніхто не підлаштовував, і цифри з нього чесні.

## API рендеру

`POST /render`, заголовок `X-Api-Key` (ключ лежить у `.env` на сервері).

```json
{ "url": "olx-pay[.]site", "mobile": true, "fullPage": false, "includeHtml": false }
```

| Поле запиту | За замовчуванням | Що робить |
|---|---|---|
| `url` | — | Адреса. Знешкоджені `[.]` і `hxxp` розпізнаються. Без схеми буде `https://`. |
| `mobile` | `true` | Емуляція Android-телефона. Жертви відкривають посилання з Viber/Telegram, і частина фішингових сторінок показує форму лише мобільним. |
| `fullPage` | `false` | Скриншот усієї сторінки, а не лише першого екрана. |
| `includeHtml` | `false` | Додати HTML (до 2 млн символів). |

Відповідь:

| Поле | Що це |
|---|---|
| `requestedUrl`, `finalUrl` | Що просили і де опинились. |
| `httpStatus` | Код відповіді головного документа. |
| `redirectChain` | HTTP-редиректи по черзі. |
| `navigations` | Усі адреси, куди переходила сторінка, включно з JS-редиректами. |
| `title`, `text` | Заголовок і видимий текст (до 5000 символів). |
| `forms` | Форми з усіх фреймів: куди відправляють, метод, поля. |
| `hasPasswordInput`, `hasCardInput` | Чи є поле пароля або картки (номер, CVV, термін дії, маска `0000 0000 0000 0000`). |
| `requestCount`, `blockedCount`, `blocked` | Скільки запитів зробила сторінка і які з них заблоковано та чому. |
| `screenshotJpeg` | Скриншот у base64. |
| `error` | Що пішло не так (див. нижче). Відсутнє, якщо все добре. |
| `elapsedMs` | Скільки тривав рендер. |

Значення `error`:

| Значення | Що означає |
|---|---|
| `dns_failed` | Домен не резолвиться, тобто вже мертвий. Браузер навіть не відкривався. |
| `blocked_internal_address` | Адреса веде у внутрішню мережу. Не рендеримо. |
| `navigation_timeout` | Сторінка не завантажилась за 20 с. Скриншот усе одно знімається з того, що встигло. |
| `net::ERR_...` | Помилка Chromium, наприклад `ERR_CONNECTION_REFUSED`. |
| `hard_timeout` | Рендер обірвано на 60-й секунді. Повертається те, що встигли зібрати. |
| `browser_unavailable` | Chromium не стартував. Дивись логи. |

Інші відповіді:
- HTTP 503 `busy`: усі слоти рендеру зайняті довше 30 с.
- HTTP 401: неправильний ключ.

`GET /health` працює без ключа і показує, чи живий браузер.

## Безпека: що вже закладено

Фішингові сторінки — ворожий код, тому захист у кілька шарів:

- **Сервіс не видно з інтернету.** Порт 8080 слухає лише на `127.0.0.1`, ззовні відкритий тільки SSH (ufw). Доступ з ноутбука йде через SSH-тунель: `ssh -L 8080:127.0.0.1:8080 root@<IP>`, після чого `http://localhost:8080` працює у тебе локально.
- **Ключ API** на `/render`, порівняння за сталий час.
- **Контейнер:**
  - не root, файлова система лише для читання;
  - без Linux capabilities, `no-new-privileges`;
  - ліміти пам'яті й кількості процесів;
  - `init` прибирає завислі процеси Chromium.
- **Мережа, два шари:**
  1. У коді кожен запит сторінки (редиректи, скрипти, картинки, відправка форм) пропускається лише тоді, коли домен резолвиться в публічну IP-адресу.
  2. Правила iptables (`firewall/render-egress.sh`, переживають перезавантаження) не пускають контейнер у приватні мережі, на `169.254.169.254` (metadata хмари) і до самого VPS.
- **Браузер:**
  - кожна сторінка відкривається в новому incognito-контексті;
  - завантаження файлів вимкнені, service workers заблоковані;
  - відео не качається;
  - сторінці дозволено не більше 400 запитів (реклама й трекери блокуються одразу й не рахуються), рендер обмежено 60 с.
- **Слабке місце:** Chromium працює з `--no-sandbox`, як майже завжди в Docker. Тому сервер має бути окремим і порожнім. Якщо сторінка зламає браузер, атакувальник отримає лише цей контейнер без доступу до мережі.

## Обмеження

- **Збірку я не тестував.** У моєму середовищі немає інтернету для пакетів, тож перший `setup.sh` — перший справжній запуск. Якщо впаде, скинь мені вивід або `docker compose logs --tail 100 render`.
- **Геоклоакінг.** Частина фішингових китів показує форму лише українським IP. VPS у Німеччині отримає заглушку або редирект на справжній OLX. Наступний крок: український VPS або проксі.
- **Виявлення headless-браузера.** Частково закрито: звичайний User-Agent, `navigator.webdriver`, повний Chromium замість headless shell. Повністю закрити не можна.

## Корисне

| Дія | Команда |
|---|---|
| Логи | `docker compose logs -f render` |
| Оновити код | Заміни файли, потім `docker compose up -d --build` |
| Новий ключ | Відредагуй `.env`, потім `docker compose up -d` |
| Більше паралельних рендерів | `MAX_CONCURRENCY` у `.env` (приблизно 1 на кожні 1,5 ГБ RAM) |
| Таймаути | `NAV_TIMEOUT_MS`, `HARD_TIMEOUT_MS`, `SETTLE_MS` у `.env` |
| Chromium не стартує з помилкою про channel | Додай `BROWSER_CHANNEL=default` у `.env`, потім `docker compose up -d` |
| Зупинити | `docker compose down` |

## Структура

```
setup.sh                 встановлення на чисту Ubuntu (VPS)
local-mac.sh             локальна спроба на Mac з Docker Desktop
test.sh                  рендер однієї адреси → result.json + shot.jpg
tools/batch_render.py    прогін CSV → render_out/summary.csv
tools/fetch_feed.py      свіжі фішингові адреси з phishunt.io → CSV
tools/evaluate.py        точність детектора на CSV з мітками → eval_out/report.md
tools/brand_audit.py     аудит клонів бренду: журнал сертифікатів + варіанти назви → audit_out/
tools/monitor.py         щоденний аудит, порівняння з учорашнім днем, сповіщення в Telegram
monitor/                 налаштування брендів для моніторингу, systemd-юніти (таймер вмикається окремо)
testdata/                50 фішингових + 12 легітимних адрес, 40 справжніх українських сайтів (legit_ua.csv)
firewall/                iptables-ізоляція контейнера + systemd unit
src/RenderService/       ASP.NET Core сервіс
  Program.cs             API, ключ, /health
  PageRenderer.cs        рендер, таймаути, збір даних, клік по кнопці-приманці
  VerdictEngine.cs       правила + LLM → вердикт
  RuleEngine.cs          бали за ознаки фішингу з поясненнями
  BrandRegistry.cs       бренди та їхні офіційні домени (brands.json)
  DomainAgeService.cs    вік домену через RDAP
  LlmJudge.cs            друга думка від Claude за текстом і скриншотами
  DomainTools.cs         зони, конструктори сайтів, скорочувачі, рекламні домени
  EgressGuard.cs         перевірка кожного запиту на внутрішні адреси
  BrowserHost.cs         один Chromium, перезапуск при падінні
  PageScripts.cs         JS, що збирає форми і текст на сторінці
  UrlInput.cs            розбір і «розшкодження» адрес
```
