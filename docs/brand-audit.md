# Аудит клонів бренду і моніторинг

Код: `phish-render/tools/brand_audit.py`, `phish-render/tools/monitor.py`, `phish-render/monitor/`. Запуск із Mac: `run-audit.sh`, `monitor.sh`.

## Аудит

### Звідки кандидати

1. **Журнал SSL-сертифікатів (crt.sh).** Будь-який домен із назвою бренду, на який випускали сертифікат, включно з уже мертвими. Запит іде в публічну базу Postgres crt.sh (веб-API з VPS повертає порожнє), JSON — запасний шлях. Пошук за **префіксом** назви: `kachorovska*` знайдеться, `fbkachorovska.top` — ні.
2. **Генератор варіантів назви:**
   - одруківки: пропущена, подвоєна чи переставлена літера, сусідня клавіша;
   - транслітерації;
   - кирилиця замість латиниці (`а`, `с`, `е`, `о`, `р` …) у зонах com, net, shop, store, online, site, top, xyz;
   - приставки: `-sale`, `-shop`, `-outlet`, `-official`, `fb-` тощо;
   - популярні зони: com, com.ua, ua, shop, store, online, site, top, xyz, sale, fashion, net.
3. **`EXTRA`** — домени з новин чи скарг, задаються вручну.

### Перевірка

1. DNS: чи домен живий. Мертві йдуть лише в `ct_history.csv`.
2. `/check` двічі: як звичайний відвідувач і як відвідувач із реклами Facebook (`fbclid` + `Referer: https://l.facebook.com/`). Попередження Cloudflare «Suspected Phishing» проходиться (`passWarning`). Перевірку «Підтвердьте, що ви людина» не обходимо.
3. RDAP: реєстратор і адреса для скарг (abuse).
4. Класифікація.

### Категорії

| Категорія | Коли |
|---|---|
| ймовірний клон | Вердикт `phishing`, або `suspicious` і сторінка згадує бренд |
| клон лише для відвідувачів з реклами | Звичайний візит бачить нейтральну сторінку, візит «з реклами» — клон |
| згадує бренд — перевірити вручну | Бренд у тексті чи заголовку, але ознак фішингу мало |
| перенаправляє на офіційний сайт | Кінцевий домен офіційний |
| домен активний, сайт вимкнений | Cloudflare Error 1001 / DNS error: клон може повернутись будь-коли |
| припаркований або продається | Маркери паркінгу |
| сторонній сайт | Бренду не стосується |
| неактивний | Не відповідає |

### Результат

Папка `audit-<бренд>-<дата>/` на Mac (після `run-audit.sh fetch`):

| Файл | Зміст |
|---|---|
| `summary.md` | Коротке зведення |
| `candidates.csv` | Живі кандидати: категорія, вердикт, пояснення, реєстратор, abuse |
| `ct_history.csv` | Усі домени з журналу сертифікатів і дата першого сертифіката |
| `<n>.jpg`, `<n>-cta.jpg`, `<n>-ad.jpg`, `official.jpg` | Скриншоти: сторінка, після кнопки, візит «з реклами», офіційний сайт |
| `audit.log` | Журнал прогону |

## Моніторинг

### Налаштування бренду: `monitor/<бренд>.json`

```json
{
  "brand": "kachorovska",
  "display_name": "Kachorovska",
  "official": ["kachorovska.com"],
  "extra": ["fbkachorovska.top"],
  "ignore": {
    "kachorovska.com.ua": "захисний домен бренду, веде на kachorovska.com",
    "crevv.com": "портфоліо дизайн-студії CREVV з брендбуком Kachorovska"
  },
  "client_chats": [],
  "client_digest": false
}
```

| Поле | Значення |
|---|---|
| `official` | Офіційні домени бренду |
| `extra` | Домени з новин і скарг, перевіряються щодня |
| `ignore` | Відомі безпечні: домен або цілий сайт (тоді й піддомени) і пояснення |
| `client_chats` | ID чатів Telegram клієнта; порожньо — клієнт нічого не отримує |
| `client_digest` | `true` — клієнт отримує й щоденне зведення, не лише зміни |

### Події

| Подія | Коли |
|---|---|
| Новий живий домен | Учора не було, сьогодні відповідає |
| Домен став клоном | Категорія змінилась на «клон» |
| Змінився вміст | Інший заголовок сторінки |
| Новий SSL-сертифікат | На домен із назвою бренду, сайт ще не відповідає (рання ознака) |
| Домен не відповідає | Два прогони поспіль |

Перший прогін лише запам'ятовує стан і надсилає зведення. Адмін отримує зведення щодня, клієнт — лише події (або й зведення, якщо `client_digest`).

### Файли на сервері

| Шлях | Зміст |
|---|---|
| `monitor/telegram.env` | Токен бота й чат адміна (600, поза архівом і контейнером) |
| `monitor/state/<бренд>.json` | Що було живим минулого разу |
| `monitor/state/<бренд>-events.jsonl` | Журнал усіх подій (для місячного звіту) |
| `monitor/runs/<бренд>/<дата>/` | Повні результати, зберігаються останні 30 |

### Розклад

systemd: `phish-monitor@<бренд>.timer` → `phish-monitor@<бренд>.service`. Щодня о 07:40 за Києвом (±10 хв), `Persistent=true` (пропущений запуск відбудеться після ввімкнення сервера), таймаут 45 хв. Ставиться `install-units.sh` вимкненим.

### Підключити нового бренда

1. Створи `phish-render/monitor/<бренд>.json` за зразком вище.
2. `bash run-audit.sh <бренд> <офіційний.домен>` — перший аудит; розбери результат, занеси безпечні домени в `ignore`.
3. `bash monitor.sh run <бренд>` — перший знімок стану, зведення прийде адміну.
4. Після згоди клієнта: допиши його чат у `client_chats`, потім `bash monitor.sh on <бренд>`.

## Обмеження

- Пошук у CT за префіксом; назви з брендом усередині ловить лише генератор варіантів. Рішення — власний потік CT-логів (див. [architecture.md](architecture.md), §10).
- Залежність від доступності crt.sh. Якщо журнал сертифікатів не відповів або відповів неповно, аудит іде на варіантах назви, а події «новий сертифікат» того дня не рахуються.
- Великі бренди дають тисячі кандидатів: аудит займає 10–15 хв і довше.
- Сторінки за перевіркою «людина» Cloudflare не відкриваються.
